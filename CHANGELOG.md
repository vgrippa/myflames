## [Unreleased]

### New features

- Adds a zoomable InnoDB ClusterSet map to **Cluster** (including when connected to an InnoDB Cluster read replica) that leads with the set status (**Healthy**, **Available**, **Unavailable** when the primary is missing, **Not OK** or **Writes fenced**, or **Unknown**), **Changes · the ClusterSet**, and per-cluster cards showing **OK**, **Misconfigured**, **Connecting**, **Not replicating**, **Writes fenced**, **Not OK**, **Invalidated** and **Not read** states. Clicking a cluster zooms into its members and routers through a saved member connection of the active group (noting `Using <server> from group <group>.` in the top bar) or a read-only metadata view when unrouted, and **Zoom out** (`⌘↑` on macOS, `Ctrl+↑` elsewhere) returns to the map.
- Adds full ClusterSet management and read-only status checks under **Changes · the ClusterSet**, with pre-review setup sheets for choosing **Remove and dissolve the cluster** or **Remove, keep the cluster running** (with a **Force** option only for dissolving an unreachable cluster), Router routing options by cluster name, replica cluster target, name and **Clone** or **Incremental** recovery, invalidating unreachable replicas during switchover or failover, and forcing dissolve when a cluster is unreachable. **Check with MySQL Shell (connects to every member)** is read-only, runs on **Read-only** connections, and displays a structured status summary above the raw output.
- Adds live **MySQL Shell progress** streaming, collapsible **MySQL Shell output** with **Copy** (noting when earlier output exceeded the 1 MiB retention limit and switching to **Copy retained tail**) across all MySQL Shell Cluster actions, and a collapsible **SQL verification** table (**Verified**, **Not read** and **Mismatch** per server) in ClusterSet results.

### Improvements

- Improves InnoDB ClusterSet reads in a **Group connection** to read consistent metadata snapshots, follow secondary members to each cluster's primary (retaining the secondary's group state when the primary cannot be read), judge **Writes fenced** by MySQL Shell's rule (`super_read_only` on with `mysql_disable_super_read_only_if_primary` disabled), flag misconfigured primary and replica `clusterset_replication` channels, and clear the replicated-copy warning only when metadata is read on the primary cluster's `ONLINE` primary with quorum.
- Improves ClusterSet review safety and verification: every review shows its **Identity check** script (checking the route UUID, ClusterSet status facts, metadata address, `view_id`, and an in-script target UUID check for replica creation), binds stored routing options for switchover, failover, removal and routing changes, requires confirmed primary unfencing for mutating changes (other than dissolve and confirmed failover), requires connection-level unreachability (`2002`, `2003` or `2005`, never timeouts or authentication errors) for every primary member before failover, refuses **Read-only** or mismatched-address spares for replica creation, applies a 60-minute no-output limit and 24-hour overall ceiling for **Clone** creation with app-quit supervision, and verifies effects with SQL on saved group routes (reporting post-start MySQL Shell errors as unknown or partial).
- The workspace's first screen loads about 10 KB less code: the Import plan dialog, the command palette's command list and the skip-loop polling of restored workspaces and other group members now load with their own chunks instead of the entry, with no change to how they open or run.
- Changes disabled action buttons in **Cluster**, **Readyset**, **Topology** > **Parameters** (**Change on every member…**) and everywhere a missing privilege or policy blocks an action: the reason no longer sits under the button; clicking the button (or pressing Enter or Space) opens a message anchored to it with the reason, how to fix it and, when a privilege is missing, the exact `GRANT` statement to copy. Escape, a click outside or **Close** dismisses the message and returns focus to the button, and screen readers hear the reason as the button's description.
- Secret redaction now skips unneeded variable-inventory, follow-up and REPLACE scans on large SQL scripts and uses faster linear scanning for SET statements and inventory literals, reducing redaction time while ensuring redaction never redacts less.
- Clicking a **Topology** > **Map** server card opens its place (**Server**, **Replication**, **Cluster**, **ProxySQL** or **Readyset**) on its saved connection, with **Back to Topology** returning to the map and **Details** keeping the inspector. Non-active members show `Using <server> from group <group>.` (in **Server** view headers, or the top bar elsewhere), and loaded **Server** views keep the earlier member's report greyed until **Refresh**.

### Bug fixes

- Fixed an issue where **Rejoin to the cluster…** stayed disabled in a healthy ClusterSet primary cluster. It can now use complete SQL evidence from that primary to establish the required `OK` status; replica clusters still require additional status checks in MySQL Shell.
- Fixed an issue where **Topology** > **Map** could claim base-table replication for a Readyset upstream from proxied identity alone or swallow an unmatched CDC-only upstream or differing CDC server. Query-only links now say `Upstream (queries)` until CDC evidence confirms them.
- Fixed an issue where **Topology** > **Map** drew a stray `Replica without a reported address` when a MySQL source's replica registration matched Readyset, or invented port `3306` for port `0`. Unmatched host-less registrations still show `Replica without a reported address`, and single-row estimates without dump evidence show `(estimate)`.
- Fixed an issue where **Topology** > **Map** member cards did not name the destination place or restore keyboard focus on **Back to Topology**, and where a long member note in the top bar could squeeze the connection picker at the 720 px window width. Map cards now name the place in their accessible label and tooltip, move focus to the place heading and back to the card on return, and keep their own width in the top bar.
- Fixed an issue where a **Skip until stopped** loop or a running dump, restore or clone on another server of a connection group lost its **Stop** or **Cancel** when you switched servers, and a reload could wrongly report the loop as stopped on the connection in use. The banner now lists running work from every server of the group, **Stop** and **Cancel** act on the server the work runs on, and after a reload myflames checks that server again (the loop itself still never resumes).
- Fixed an issue where a running **Skip until stopped** loop could disappear after a failed status check on reload, or a running dump, restore or clone could disappear when its server left a connection group. Reload now keeps the server's loop tracked and retries its status until it responds, a running maintenance job whose server left the group is named in a status note until the next reload, and **Stop**, **Cancel** and status notes now report accurately when saved connections could not be read or when a server was never in a group.
- Fixed an issue where closing a **Query editor** tab while its statement was still running, then quitting myflames, could lose that run's history and audit record. Quitting now waits briefly for runs of closed tabs to finish writing.

### Security fixes

- Clipboard copy across the workspace (Copy buttons, menus and text selections outside the SQL editor, including inside embedded plan, comparison and **Learn** lesson previews, excluding password inputs) now normalizes CRLF (`\r\n`) to LF (`\n`), keeps tabs and LF, and replaces terminal controls, Unicode line/paragraph separators and bidirectional text controls and marks (C0 controls other than tab and LF, including lone CR; DEL `U+007F`; C1 controls `U+0080`–`U+009F`; `U+2028` and `U+2029`; `U+061C`, `U+200E`, `U+200F`, `U+202A`–`U+202E` and `U+2066`–`U+2069`) with single ASCII spaces so SQL comments, TSV rows and JSON strings keep their boundaries. Copy button and menu confirmations, and status notes for sanitized selection copies, report how many control characters were replaced (CRLF normalization is not counted). **Compare servers** > **Accounts** SQL export (**Copy** and **Download .sql**) now omits any account, role or grant whose user, host or object name contains characters outside printable ASCII or a backslash, naming the left-out account and the reason in a SQL comment.
- Name-gated SQL copies built from server-reported names in the **Tables** row menu (**Copy table name**, **Copy SELECT query**, **Copy SELECT COUNT(\*)**), **Tables** missing-primary-key and online-rebuild statements (checking schema and table names), and **Indexes** row-menu and unused-index copies (**Copy index name**, **Copy DROP INDEX SQL**, **Copy DROP PRIMARY KEY SQL**, **Test without**, **Drop**) are offered only when those checked names are printable ASCII without a backslash; otherwise the action stays disabled and explains why, because the mysql client's line editor can read other bytes as editing keys and a backslash can start a client command. Account SQL suggested in the full analysis report and **Config** now quotes user and host names as identifiers and checks those names before offering SQL copies. Other copied SQL (such as suggested index DDL, `ANALYZE TABLE` in **Plans** and column or index names embedded inside missing-primary-key statements) is not gated by this name check.
- Shared SQL copy confirmations (including **Tables**, **Indexes**, **Table structure**, **Schema versions**, **Locks**, **Compare servers** > **Accounts**, **Analysis** `ANALYZE TABLE` and index suggestions, **Statement** / **Query** details, **Accounts**, **Import CSV** and **Server** views using the shared SQL copy block) append a warning note when a lexical check finds a possible mysql or MariaDB client command: a short backslash command (such as `\!` or `\G`, excluding `\N`) outside strings, backtick identifiers, `#`/`--` line comments and plain `/* */` comments, including inside `/*! */` executable comments and `/*+ */` optimizer hints, or a named command at a line or statement start such as `source` or `system`, including after leading `/*! */` comments or `/*+ */` hints. A line whose first word names a client command also warns even inside quotes or comments. Separate MySQL and MariaDB passes try backslash escapes on and off, MySQL dollar quoting on and off and MariaDB's `ANSI_QUOTES` on and off; a match outside quotes in any pass produces the note. This is a warning heuristic, not a guarantee: a `sql_mode` change inside the copied script, the client's `DELIMITER` prefix rule (such as `delimiterX`), or a delimiter already set before the paste can hide later commands, and backslashes in option-file (`my.cnf`) lines can trigger false warnings. Every copy through the shared Copy helpers now carries the warning, including **Export as SQL**, **Query digest**, **Plans**, **Audit**, **Object changes** and command blocks, and the warning appears inside an open dialog (such as **Import CSV** or **Export as SQL**) instead of behind it.
- **Maintenance** > **Dump** and **Restore** SQL tool commands (`mysqldump`, `mariadb-dump`, `mysql`, `mariadb`) are quoted with POSIX shell quoting and labeled as POSIX shell commands (on Windows, noting they target a POSIX shell such as WSL or Git Bash rather than Command Prompt).

### Known issues

- Connect InnoDB ClusterSet members using direct host and port addresses rather than a load balancer or a statement-routing proxy such as ProxySQL or Readyset. MySQL Shell's AdminAPI opens internal member and metadata sessions whose UUID and view it does not expose, SQL reads send their server UUID check and follow-up query in separate packets, and replica creation and member rejoin open MySQL Shell's own target connection after the pre-call UUID check.
- When reviewing ClusterSet switchover, failover, removal or routing changes, a replicated metadata copy can lag behind the primary, the in-session MySQL Shell guard does not recheck routing options after the fresh pre-send read, and a Routing Guideline's document content can change without its stored guideline ID changing.
- With MySQL Shell 9.7.1, **Dissolve ClusterSet…** skips Shell's primary-last cleanup step and can leave `clusterset_replication` managed failover rows in `performance_schema.replication_asynchronous_connection_failover_managed` on former replica members. SQL verification flags leftover rows so you can inspect and clean up every reachable instance afterwards.
- Any MySQL Shell error after a ClusterSet action starts (including a precondition error such as a missing member during **Dissolve ClusterSet…**) reports **Unknown or partial**, because MySQL Shell can acquire locks that install persistent locking-service UDFs without binary logging before raising the error.
