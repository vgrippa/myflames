# MyFlames Project Rules

This is the canonical project rules file for every coding agent. `CLAUDE.md` and `GEMINI.md` are loading adapters. Read [docs/DEVELOPER_REFERENCE.md](docs/DEVELOPER_REFERENCE.md) before changing a feature; it holds the detailed feature contracts.

## Project Overview

**myflames** is a MySQL and MariaDB performance workspace. Its core visualizes `EXPLAIN ANALYZE FORMAT=JSON` output as interactive flame graphs, bar charts, execution trees, and Visual Explain–style diagrams; around that it finds expensive statements (top and running queries), shows locks and deadlocks, and compares plans. New performance views go in the workspace's Server place (see ROADMAP.md "Performance workspace"). It requires MySQL 5.7+ (Percona Server for MySQL included; 5.7 is end of life and is read with what it lacks stated in plain sentences) or MariaDB 10.11+/11.4+ and Python 3.7+ with no external dependencies.

Inspired by [Brendan Gregg's FlameGraph](https://github.com/brendangregg/FlameGraph) and [Tanel Poder's SQL Plan FlameGraphs](https://tanelpoder.com/posts/visualizing-sql-plan-execution-time-with-flamegraphs/). **Never remove this inspiration / credit line** from the README (or anywhere else it appears). Brendan Gregg and Tanel Poder are the origin of this work and must always be acknowledged.

## Development Workflow & Testing

- **Mandatory Tests**: Every new feature or logic change in the Python package MUST include a corresponding test case.
- **Verification**: Use the test-pro skill (`/test-pro` in Claude Code) to ensure coverage and verify that MySQL explain data is parsed correctly before completing a task.

## Architecture (Python package: `myflames/`)

1. **`parser.py`**: Single entry point. Builds a unified tree. Auto-detects MySQL vs MariaDB format. MariaDB normalization (`_normalize_mariadb*` functions) converts MariaDB's `query_block/nested_loop/table` structure into MySQL's `operation/inputs` tree before `parse_node` processes it. `analyze_plan(root)` scans for full_scans, hash_joins, etc.
2. **`cli.py`**: Argument parsing and SVG height patching for the analysis panel.
3. **Renderers**: `flamegraph.py`, `output_bargraph.py`, `output_tree.py`, `output_diagram.py`, `output_workbench.py` write standalone `.svg` output. (The treemap view was removed; `--type treemap` is a deprecated alias that warns and renders the bar chart.)
4. **Chart runtime**: HTML reports, `explore` pages, and the workspace draw every chart with the TypeScript runtime in `apps/workspace/src/charts/` (built by `npm run build` into the committed `myflames/assets/myflames-charts.js`, inlined by `chart_assets.py`). Python stays the source of every semantic decision: `chart_data.py` emits `chart-data-1.0` for reports and `explore` pages and `chart-data-2.0` for the workspace (`docs/schemas/chart-data-*.json`; 2.0 stores each analysis message once, and the bundle reads both) using the same helpers as the Python renderers, and the TS only lays out and handles interaction. Keep both renderers in step: `apps/workspace/test/parity.mjs` compares them on every fixture, `test_chart_data.py` fails if the committed bundle is older than its sources or over 80 KB. Charts are instance-scoped (no page-wide IDs), set plan text with `textContent` only, and capture Ctrl+F only while focus is inside the chart. Visual Explain's fit never renders text below 11 px: `MIN_TEXT_PX` in `charts/core/zoom.ts` and `SMALLEST_TEXT_PX` (the smallest font in `WORKBENCH_CSS`) in `charts/workbench.ts`, with the same two constants in `myflames/workbench.js`, clamp the fit ratio by the screen scale (1 in the workspace, `getScreenCTM()` in reports and the standalone SVG); a plan larger than that view starts at its first inputs and pans, Fit, a double click and a resize while fitted return to that opening view, and only an explicit zoom out goes smaller. The Execution tree prints Total on every row, leaves included (a leaf's total equals its self time), and `—` in Self and Total for an unmeasured operator, in `output_tree.py` and `charts/tree.ts` alike.

## Key Constraints & Coding Standards

- **No External Dependencies**: Stdlib only. Python 3.7+ compatible (no walrus operator, no `match` statements).
- **Single Parser**: Never parse JSON in output modules; always use `parser.parse_explain`.
- **SVG Rules**: Always update both `height` AND `viewBox` together. Use `_wrap()` for info panel text.
- **Preserve Order**: Do not sort `inputs[]` in the JSON; order is semantically significant (outer vs inner table).
- **Preserve Inspiration Credit**: Never remove the "Inspired by Brendan Gregg's FlameGraph and Tanel Poder's SQL Plan FlameGraphs" line from the README or anywhere else. This attribution is load-bearing for the project and must always remain. In the workspace app it lives in the **About myflames** window (Settings menu), like a desktop app's About, rather than a footer on every screen; README (near the top), NOTICE, this file, CLAUDE.md and HTML report footers keep it.
- **License: Apache-2.0** (`LICENSE`, `NOTICE`). myflames began as a fork of FlameGraph (CDDL 1.0); the flame graph renderers (`myflames/flamegraph.py`, `apps/workspace/src/charts/flamegraph.ts`) are clean-room rewrites from a functional spec. Never copy or consult code from `flamegraph.pl`, the FlameGraph repo, or this repository's pre-2.4 history of those files when changing them. Releases up to 2.3.0 stay CDDL 1.0. The inspiration credit is separate from the license and must stay.
- **Commit & release-note conventions**: Do NOT add `Co-Authored-By` or any AI-attribution trailer to commit messages. Keep commit messages, CHANGELOG entries, and GitHub release notes professional: no emojis, no "generated with" footers, and no meta-commentary that an AI/LLM authored or verified the work. Legitimate product references (the tool targets LLMs/agents; `--tokenizer claude` uses Anthropic's `count_tokens`) are fine.
- **Documentation is mandatory, not optional**: Any change to a user-facing parameter, subcommand, flag, or core feature (adding, renaming, changing behavior, or removing) MUST update the docs in the same change: `README.md` (the relevant section + the Agent/CI subcommands block + any CLI reference), `AGENTS.md` and `docs/DEVELOPER_REFERENCE.md`, the `CHANGELOG.md` `[Unreleased]` section, and any affected file under `docs/` (walkthroughs, examples) and `ROADMAP.md`. A PR/commit that ships a CLI surface change without the matching doc edits is incomplete. When renaming, keep a deprecated alias and document it.

- Host-and-port client connections, including localhost, use TCP in every connector, editor and lifecycle path. Classic client option files set `protocol=TCP` unless an explicit socket selects `SOCKET`. MySQL Shell uses an explicit port to select TCP; a socket connection omits port. Lifecycle control reads share the connector's 64 MiB stdout and 1 MiB stderr caps. Editor engine detection uses both `@@version` and `@@version_comment`. A connection with `ssh_host` (optional `ssh_user`, `ssh_port`) reaches its database through `ssh_tunnel.py`: the system `ssh -N -T -o BatchMode=yes -o ExitOnForwardFailure=yes -o LogLevel=DEBUG1 -o UpdateHostKeys=no -o PermitLocalCommand=no ... -L 127.0.0.1:LOCAL:DBHOST:DBPORT -- TARGET` (never ClearAllForwardings, never a Unix-socket forward: the client would treat it as secure transport and send the password in clear) as an argument list in its own process group, on POSIX started by `ssh_watchdog.py` (it leads the group and stops ssh when its stdin pipe from the opening process closes, so a tunnel never outlives that process, SIGKILL included), on Windows tied to it by a job object (below), with the user's real home and agent (`MYFLAMES_SSH_HOME`, `MYFLAMES_SSH_AUTH_SOCK`) and an allowlisted environment, keys and agent only, never an SSH password (none is accepted or stored). On Windows each ssh.exe starts suspended (`CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW | CREATE_SUSPENDED`), is assigned by its process handle to the opening process's single job object (`win_job.JOB`, created on first use with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, its handle not inheritable and never closed by myflames, so Windows ends every ssh in it, with what ssh started, however that process ends, `taskkill /F` included) and only then resumes. When creating the job, assigning or resuming fails, `_join_job` kills ssh before it ran and refuses the tunnel with "Windows could not tie the SSH tunnel to myflames (job object: REASON), so ssh was stopped before it connected. Nothing was sent."; an interrupt (Ctrl+C) while ssh.exe waits suspended also kills it before the interrupt is raised again. SSH host and user follow strict patterns and never start with `-`; VERIFY_IDENTITY and a socket are refused with SSH. Every client path (`MySQLConnection._invocation_defaults`, the editor session's lease, `lifecycle._credentials`) writes `host=127.0.0.1`, the tunnel's port and `protocol=TCP`, and a connector with `ssh_host` but no tunnel refuses to build an option file. A tunnel is ready only when ssh's own DEBUG1 lines say "Local forwarding listening on 127.0.0.1 port LOCAL.", then its `[port listener]` channel, then "Entering interactive session." while ssh runs; never on a TCP accept or probe (another local program can listen on the port first), and debug lines are matched, never kept or shown. A lease whose ssh ended is never reused (`Lease.alive`). Windows ssh is `%SystemRoot%\System32\OpenSSH\ssh.exe`, else `ssh.exe` in an absolute PATH folder; PATH searches skip relative entries. Tunnels are keyed by SSH host, user and port and the database host and port, leased per client invocation, editor session or tool run, closed after 300 s without users and at shutdown (a timer starts `TUNNELS.close_all()` at the latest `WorkspaceServer.TUNNEL_CLOSE_SECONDS` after shutdown starts, then each stop waits on SIGTERM and SIGKILL; the CLI turns SIGTERM and SIGHUP into an exit with status 128 + signal so atexit closes them), at most 8, and started again (never under a running statement) after one dies. Tunnels and dump, restore and clone tools together list at most `ToolGroups.MAX_GROUPS` (16, equal to the desktop's `MAX_TOOL_GROUPS`); beyond it a start is refused. The SSH target joins `dbops.connection_identity`, `workspace_store.ENDPOINT_FIELDS`, the saved-password fingerprint and `connectionKey` only when set (identities without SSH are byte-for-byte unchanged), and audits record it (`ssh` column, `connection.ssh`). CLONE through SSH is refused on either side; the MariaDB error-log file, replication loopback sources and physical-backup locality treat SSH as remote.
- KILL never ends `Group Replication Data Stream subscription` connections. Use `locks.is_group_replication_command` for both Kill and Sessions: MySQL process-list COMMAND columns truncate the name to `Group Replicatio` (16 characters); accept exact prefixes of at least 16 characters through the full name. The shared kill guard refuses with the Cluster guidance, audits the refusal, and Sessions exposes `kill_blocked_reason` with the same text and marks the row as a replication system thread. Bulk Kill validates every target before policy gating and audits every refusal or failure, including before connection. It reads server metadata once per batch and includes the server identity in each existing target SELECT; it rechecks each target, transaction and saved policy immediately before sending, skips settle sleeps, and uses one final process-list snapshot for results and audit after-state; an unreadable snapshot stays unknown.
- `HANDLER ... OPEN` is risky because its metadata lock lasts until CLOSE or the session ends; HANDLER READ and CLOSE stay reads. `connector.explain_analyze` sets `explain_json_format_version` only from MySQL 8.3 and uses the shared actionable version-error mapping.
- Query digest's slow log sources (`slow_queries.py`, `slowlog.py`) replace the retired "Slow queries over 1 s" ranking (`/api/live/slow-queries`, `slow-queries-1.0` and `discover.slow_queries_report` are removed); unmeasured slow-log counters are null. ## Review corrections (2026-09-15)

- Treat parsed operator times as milliseconds. `render_bargraph` converts display
  units internally; callers must not scale the shared tree.
- Comparison pairs repeated labels by traversal occurrence. Preserve all
  occurrences; this is not structural matching across reordered plans.
- Render/compare input and output failures return 2 with a stderr diagnostic.
- MySQL TempTable is limited per table by `tmp_table_size`; MEMORY also uses
  `max_heap_table_size`. Collect `internal_tmp_mem_storage_engine` before making
  engine-specific recommendations. Configuration size alone does not prove a spill.
- Scalar/streaming aggregation is linear in input rows; sorting is a separate
  operator, and DISTINCT or ordered aggregates require separate accounting.
- Test current MySQL versions with the configurable fixture generator and
  `MYFLAMES_MYSQL_FIXTURES`; see `test/README.md`. Keep fresh version corpora
  separate from the committed fixture directory unless intentionally updating it.

## Commands

Invoke subcommands with `python3 -m myflames <command>`. For flags, schemas, implementation paths, safety contracts, and feature-specific tests, read [docs/DEVELOPER_REFERENCE.md](docs/DEVELOPER_REFERENCE.md). The default command renders a plan with `--type`; `--hide-literals` replaces literal values with `?` in its HTML and JSON.

### Workspace refinements (2026-10-16)

Refresh all reads every Server section, including unopened views, with at most three concurrent section reads. Full analysis owns a separate phase. Preserve connection/scope consent, single-flight reads, cancellation and stale-response guards. Maintenance only detects tools; refresh never starts jobs or upgrade checks. Imported diagrams are preserved.

Home shows the installed version and links to releases. Update status stays unverified until the user clicks **Check for updates** (Home's version footer or About myflames); nothing asks GitHub automatically. The outcome and its time are kept in the workspace store and shown in local time, and a result older than 24 hours is shown as the last result, never as current. Query editor, Query digest, Database diagram, Schema versions and Plans share the SQL workspace navigation group. Parameters stages inline edits and batch reviews (up to 25 changes) from server variable metadata and the generated `mysql_sysvars.py` catalog; legal scope selection, exact SQL review and Session editor ownership remain mandatory. Explanations stay in the inspector.

Tables/Indexes workspace reports include complete scoped inventories with a 100,000-row category ceiling and existing schema-size consent. Paginate after sorting; exports include all filtered rows. CSV protects formula-like values, HTML escapes names and values, and PDF uses the system print dialog. DATA_FREE never represents per-index fragmentation; reusable-space percentages require known sizes and file-per-table ownership. Preserve unknowns. CLI row limits remain unchanged. Tables and Indexes put their filter (Filter tables in Tables), count, Rows, Export and paging in `PaginatedReportTable`'s shared controls group, while schema scope and Fresh numbers stay in the view toolbar; every Tables list marks Table as its flexible primary column with a 220 px minimum. Indexes advice holds explanations and copyable SQL only: Set invisible/visible (Set ignored/not ignored on MariaDB) and Drop index have one home, the inspector's action bar, with row menus as contextual entry points.

Parameters uses **Review and apply** for batch edits, **Stage value for review** in the inspector to stage one value in the table, and **Change this parameter…** in the inspector for single-parameter modes. Permission details appear inside the review dialog; the buttons do not show an Unverified badge. Existing confirmation and privilege checks still apply.


Workspace interaction guards: privilege reads use the successful-connect or
committed-password revision, never password keystrokes; Set, blur and Enter
commit once per changed value. Saved-connection reads adopt the newest response.
Parameters, Instruments and Users and roles use `useOpenRead`, keeping an old
report greyed on an on-screen connection switch until Refresh. Account selection
asks Review changes, Discard or Cancel when grants are staged. Shared SQL builders
in `sqlIdent.ts` escape identifiers and literals. Row menus use the measured
`ContextMenu`, with view actions before copy actions; resize cancellation always
clears the drag. Full analysis elapsed time belongs to the read owner, outside
Tuning's mount.
