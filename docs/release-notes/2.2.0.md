# myflames 2.2.0 (2026-06-30)

myflames 2.2.0 is a Python command-line tool (Python 3.7 or later, no external dependencies) that turns MySQL and MariaDB EXPLAIN ANALYZE output into flame graphs, other plan views and compact digests for AI agents.

## Bug fixes

- Fixed an issue where the advisor suggested `mrr_cost_based=on` when `optimizer_switch` had `mrr=off`. That setting has no effect while MRR is off, so the advisor now suggests `mrr=on`, and `mrr_cost_based` still decides for each query.
- Fixed an issue where the Visual Explain diagram showed only the first two branches of a join or `UNION` with three or more inputs, such as a multi-branch `UNION ALL`.
- Fixed an issue where a plan file holding valid JSON that is not an object, such as a number or an array, failed with an unclear error. myflames now reports a clear error, and the MCP tools no longer crash on such input.
- Fixed an issue where `check` accepted a misspelled `--fail-on` trigger, matched nothing and let a CI gate pass. An unknown trigger now fails with exit code 2.
- Fixed an issue where rendering a plan with no flame graph data, because every self time was zero, exited with code 1. It now exits with code 2 for bad input, and code 1 stays reserved for a tripped finding.
- Fixed several advisor inaccuracies. MariaDB BNLH advice names `join_cache_level >= 3` as the setting to change, `rowid_filter` is listed for MariaDB 10.4 and later, the non-sargable join note says a functional index on the exact expression can be used, and `const` and `system` access is O(1).
- Fixed inconsistent tooltip escaping across the views. Newlines and single quotes are encoded the same way everywhere, and long tooltips are shortened before escaping so a character entity is never cut in half.
