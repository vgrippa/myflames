# myflames 2.0.0 (2026-06-05)

myflames 2.0.0 is a Python command-line tool (Python 3.7 or later, no external dependencies) that turns MySQL and MariaDB EXPLAIN ANALYZE output into flame graphs, other plan views and compact digests for AI agents.

## Release highlights

- The new `tokens` command prints a compact text digest of a plan and shows how many tokens and how much cost it saves compared with the raw plan.
- The new `check` command turns plan findings into a CI gate that fails with a non-zero exit code.
- The `myflames-mcp` server lets AI agents analyze, digest and compare plans directly.
- All commands share one exit code contract, and bad input now exits with code 2.

## New features

- Adds the `tokens` command, which compares the tokens and input cost of handing an LLM the myflames digest instead of the raw plan. Counts are an offline estimate by default. `--exact` gives exact Claude counts through Anthropic's `count_tokens` with the optional `myflames[tokens]` extra, and `--digest` prints the digest itself.
- Adds the `findings` command, which lists ranked warnings and suggestions, each with a confidence level, as text or as JSON with `--json`.
- Adds the `check` command for CI pipelines. `--fail-on` takes categories, severities or `any`, and `check` exits with a non-zero code when the plan trips one of them.
- Adds `diff` as another name for `compare`, with a `--digest` mode for a compact text diff and a `--json` mode for a structured result.
- Adds an MCP server, `myflames-mcp`, so AI agents can call myflames directly. Install it with the optional `myflames[mcp]` extra. It offers the `analyze_plan`, `digest_plan`, `compare_plans`, `explain_optimizer_switch` and `explain_query` tools.
- Adds an "Agent-ready" panel to every HTML report that shows the token and cost saving of the digest, and a "Made with myflames" footer with the credit to Brendan Gregg and Tanel Poder.

## Improvements

- All commands use the same exit codes: 0 for success, 1 when a `check` gate trips and 2 for bad input such as a missing file or invalid JSON. Rendering a plan that cannot be parsed now exits with 2 instead of 1.
- `tokens` and `findings` accept `-o` (`--output`) to write to a file. Machine output goes to stdout and messages go to stderr, including the status line of `check`, so pipes into `jq` and redirects stay clean.

## Packaging notes

- The core package still uses only the Python standard library. The optional extras `myflames[mcp]` and `myflames[tokens]` add the MCP server and exact Claude token counts.
