# myflames 3.5.0 (2026-11-20)

myflames 3.5.0 is available for macOS on Apple Silicon and, as an unsigned preview, for Windows x64.

## Release highlights

- **Group connections** let you open a connection group as one connection with a **Server:** picker across single-server views and the **Query editor**, and run **Cluster** member actions through each member's saved connection.
- **Cluster** keeps every action for the cluster kind visible with the reason it is disabled and the exact `GRANT` statement to copy when a privilege is missing, and reads InnoDB ClusterSet topology from a read replica.
- **Settings > Client tools…** can download Oracle's MySQL Shell 9.7.0 on demand, and **Settings > Appearance** adds font and text size controls for the interface and for SQL and code.
- The **Cluster**, **Replication**, **ProxySQL** and **Readyset** topologies have a new three-dimensional stage look, and the **Query editor** toolbar adds **Find**, **Find and replace** and an **Editing actions** menu.

## New features

- Adds **Group connections** in the connection picker, opening a connection group under the strictest safety of its members. Single-server places and the **Query editor** have a **Server:** picker that starts on the primary or source, and every view header and query tab names the server.
- Adds **Edit group…** in the connection picker, the status bar and Home's **Connections** place to rename a group, add or remove saved connections, or delete the group while keeping its saved connections. Removing a member moves open views to the primary.
- Adds Group connection support for **Cluster** member actions: each runs through that member's saved connection, or through the active ONLINE member with quorum for **Rejoin to the cluster…**. When no saved connection in the group is confirmed as that member, **Cluster** offers **Edit group…**.
- Adds a **Text** group to **Settings > Appearance** to choose the interface font and text size (12–16 px) and the code font and text size (11–20 px) for the **Query editor** and all SQL and code text, with a live preview and **Restore default text settings**. Inter and JetBrains Mono are included, alongside fonts installed on the computer.
- Adds **Get MySQL Shell** to **Settings > Client tools…**: when no usable copy is found, it downloads the pinned MySQL Shell 9.7.0 build directly from Oracle into myflames's data folder (myflames redistributes nothing), with a progress bar, **Stop** and SHA-256 verification before anything runs. The downloaded copy is detected immediately and preferred over other installations.

## Improvements

- **Cluster** now keeps every action for the cluster kind visible on the Cluster overview (**Switch to single-primary…**, **Switch to multi-primary…**, and ClusterSet switchover, failover and rejoin).
- Each member's or node's inspector in **Cluster** keeps every action for the cluster kind visible (**Make primary…**, **Stop Group Replication…**, **Start Group Replication…** and **Rejoin to the cluster…**, or on MariaDB Galera **Desync this node…**, **Resync this node…** and **Bootstrap a Primary component…**).
- **Cluster** actions that cannot run stay disabled with the reason and fix in plain words under them. When the connection's account lacks a privilege, they show the exact `GRANT` statement for that account to copy ("Run it as an administrator, then Refresh.").
- **Cluster** now shows InnoDB ClusterSet topology when connected to an InnoDB Cluster read replica, reading the replica's replicated metadata copy and noting that it may be behind the primary cluster. After a **Cluster** action runs, the before-and-after table states in plain words why any value was not reported instead of saying "Not readable".
- The **Cluster**, **Replication**, **ProxySQL** and **Readyset** topologies have a three-dimensional look: the diagram sits on a lit stage, servers float above it, and the group's line lights up only when every member is healthy. The **Depth** and **Pause motion** buttons are gone; motion still stops with your system's reduced motion setting, and each place's ⓘ explains what it means.
- The installed version moved from the window status bar to the top of the sidebar beside the myflames name; choosing it opens **Settings > Updates and news**, which now holds the update status, **Check for updates** and **View releases**.
- A badge beside the sidebar logo alerts you and names the new version when an update is available, downloading or ready. On the compact icon rail, the version text hides and the logo's tooltip names the version.
- The **Query editor** toolbar has **Find** and **Find and replace** buttons, and an **Editing actions** menu lists every editing command with its shortcut, including **Toggle Tab moving focus**.
- The workspace now loads **Plans** and **Learn** on demand, reducing the code needed to open the first screen.

## Bug fixes

- Fixed an issue where myflames could fail to open, with **Could not open myflames: The Python backend did not become ready in time.**, on a computer where DNS lookups are slow. The workspace no longer looks up a host name for its local address when it starts.
- Fixed an issue where the workspace could fail to load a view or the **Query editor** under load, leaving the page stuck on **Loading**. The local server now queues connection bursts instead of refusing them; when it is still busy, the workspace retries while opening or shows an error with **Try again**.
- Fixed an issue where **Cluster** offered MySQL Shell actions on MySQL Shell older than 8.0.32, which cannot read myflames's private credentials file, and offered **Rejoin to the cluster…** without requiring metadata 2.0.0 or later and a verified `OK` ClusterSet status. Older MySQL Shell installations now show the version found and offer **Get MySQL Shell**.
- Fixed an issue where a **Cluster** action run through MySQL Shell could report a wrong error, or an error location taken from earlier output. When MySQL Shell's output does not end with its own error location, myflames now reports the outcome as unknown and reads the cluster again to show any change that was made.
- Fixed an issue where the **Query editor** refused a MariaDB `CREATE PACKAGE` or `CREATE PACKAGE BODY`, or an `ALTER EVENT` with a `BEGIN ... END` body, entered under a custom `DELIMITER`, as more than one statement. Each is now confirmed as one statement.
- Fixed an issue where opening the **Query editor**, or running a script or a reviewed change, with an account whose MySQL password has expired showed a generic client failure. myflames now shows the server's error 1862, which says the password has expired and must be changed.
- Fixed an issue where the table data editor's review button read **Review 1 changes** for a single change.
- Fixed an issue where **Explain** with **Parameters** refused statements with double-quoted text or a backslash-escaped quote even when the tab's session knew its `sql_mode`. Parameters are now filled the way that session reads the statement.
- Fixed an issue where the schema note on a **Top statements** tab could name a different schema than **Run analysis** used after a `USE` in the tab's session. The note, **Run**, **Explain**, **Run analysis** and the **Database** picker now follow the same schema.

## Security fixes

- Fixed an issue where reviewed actions (**Cluster**, **Users and roles**, **Kill**, **Variables** and **Replication** skips) and confirmed **Query editor** writes checked the server on a separate read, and MariaDB Galera did not compare the node UUID (`wsrep_gcomm_uuid`). Changes now share one request with those checks, so a proxy or router cannot confirm one server and change another.
- Fixed an issue where **Cluster** and ClusterSet actions run through MySQL Shell did not confirm the global session's `server_uuid`, the cluster's group UUID, and the ClusterSet name and the group UUIDs of its member clusters. Those actions now confirm them before acting.
- Fixed an issue where **Stop** and closing a tab in the **Query editor** sent `KILL QUERY` on an unconfirmed helper connection, risking the wrong server behind a proxy or after failover, or another MariaDB Galera node sharing server name, id and port. The helper now confirms the server (and Galera node UUID) before sending `KILL QUERY`, refusing if unconfirmed.

- Fixed an issue where the **Query editor** could read SQL text differently from the server or the client, so a statement hidden in an executable comment (`/*!...*/`, `/*M!...*/`), an optimizer hint, or text quoted under `ANSI_QUOTES`, `NO_BACKSLASH_ESCAPES` or MariaDB `MSSQL` mode could run without review. The **Query editor** now reads SQL the way the server version, its `sql_mode` and the client read it, asks to review any change those rules reveal, and refuses text that the server and the client would split differently, with a message that says what to change.
- Fixed an issue where a `DELIMITER` or `charset` client command placed after an executable comment, or text that runs as several statements on the server but as one for the client, could change what the client sent. The **Query editor** now refuses it before review and asks for each statement on its own line.
- Fixed an issue where a stored program, a compound block or a run of several statements could carry more than one schema change, or a `DROP DATABASE`, under a single confirmation. Each schema change is now reviewed on its own, `DROP DATABASE` asks you to type the database name, and a run that drops more than one database is refused.
- Fixed an issue where the client running the **Query editor** or a **Users and roles** password change could keep a stale view of `NO_BACKSLASH_ESCAPES` or MariaDB `ANSI_QUOTES` after a stored program changed `sql_mode`, so it could split a statement differently from what you reviewed. myflames now refreshes the client's view and confirms it with a short check before sending such a statement; if the check fails, that statement and the ones after it are not sent, and the message says which statements already ran.
- Fixed an issue where **Import CSV** wrote a value containing a backslash as quoted text whose meaning depended on the client's view of `NO_BACKSLASH_ESCAPES`. Such values are now written as hexadecimal literals.

## Known issues

- In the **Query editor**, **Stop** cannot interrupt a running statement when a proxy or load balancer routes the helper connection to a different server than the tab's session: **Stop** refuses to send `KILL QUERY` and the statement continues on the original server.
- In the **Query editor**, **Stop** cannot interrupt a statement in a stored routine (`CALL`), a prepared statement (`EXECUTE`) or one the server rewrites in its process list (such as `CREATE USER` with a password), because the server does not show the tab's statement for that session. **Stop** says so, sends no `KILL QUERY`, and the statement continues.
- A MariaDB server outside a Galera cluster has no server UUID, so reviewed actions confirm it by its `server_id`, host name and port. Two such servers that share all three cannot be told apart; give every standalone MariaDB server its own `server_id`.
