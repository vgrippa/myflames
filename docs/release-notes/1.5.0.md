# myflames 1.5.0 (2026-04-25)

myflames 1.5.0 is a Python command-line tool (Python 3.7 or later, no external dependencies) that turns MySQL and MariaDB EXPLAIN ANALYZE output into flame graphs, other plan views, HTML reports and interactive lessons.

## Release highlights

- The advisor gives corrected advice for block nested loop and hash joins, MRR and `innodb_flush_log_at_trx_commit`.
- Every advisor finding carries a rule ID and a severity that CI pipelines can gate on.
- Every plan node has a stable ID that the JSON sidecar, the SVG and the warnings all refer to.
- The HTML report's **Collected environment** panel shows readable sizes, `optimizer_switch` chips and a clickable list of tables.

## New features

- Adds a rule ID and a severity to every advisor finding, so CI pipelines can gate on specific rules without matching the text of the advice.
- Adds a stable ID to every plan node, the same on every run of the same plan. The JSON sidecar uses these IDs in a new plan tree, in warnings and in complexity entries, links to its published JSON Schema and adds a summary of environment findings.
- Adds a JSON sidecar to comparison reports. It is written next to the report and describes the differences between the two plans in a machine-readable form.
- Adds the myteach lesson catalog. `myflames teach --index -o PATH` writes it as an HTML page, and every report gets a myteach section that links to it and lists the lessons that match the plan.
- Adds two lessons: one on covering indexes, including how InnoDB adds the primary key to secondary indexes, and one on buffer pool warmup.

## Improvements

- The advisor tells `innodb_flush_log_at_trx_commit=2` and `=0` apart. Each has its own severity and explanation: with `2` a transaction can be lost only in an operating system crash, and with `0` in any crash, including a `mysqld` crash.
- Improves MariaDB support: plans that use "range checked for each record" access are now converted into the same plan tree as other MariaDB plans.
- Improves HTML report accessibility with a visible keyboard focus ring, a skip link and higher-contrast secondary text that meets WCAG AA.
- HTML reports, the standalone complexity SVG and lessons respect the `prefers-reduced-motion` setting and play their animations almost instantly when it is on.
- Sidecar files use a JSON-LD envelope so search crawlers and LLM retrieval tools can read them, and every HTML report links to its sidecar in the page header.
- The HTML report has a two-row sticky header: the title and toolbar, then the engine, version, operator count, total time and generation time.
- Glossary terms in HTML reports link to their glossary entry and open it. Terms that have a matching lesson also get a **Learn** button.
- The **Fix first** card always says why its action matters, and it shows a ready-to-run `CREATE INDEX` statement when the top suggestion is an index.
- Improves the **Collected environment** panel. Byte values read as sizes such as 128 MB, with the raw bytes in a tooltip. `optimizer_switch` appears as a list of on and off chips, and the **Tables** card expands each table to show its columns and indexes with PK, UNIQUE and INDEX badges.
- The flame graph colors each bar by one of 12 access type families and keeps red for advisor warnings.
- The treemap uses a squarified layout instead of slice-and-dice, so its cells stay close to square.
- Search in the bar chart and treemap shows an accurate `Match N/M` count and responds to the `n`, `N` and `Esc` keys.
- Long labels in the bar chart, treemap and diagram are shortened in the middle with an ellipsis, with width estimates that account for CJK characters. Bar chart and treemap SVGs now include a `viewBox`.
- Complexity charts mark the cheaper curve when lower is better. The axis label says "lower = better", and the curve at the cursor gets a check mark and an "N× cheaper" label.
- The nested loop lesson animates smoothly, draws each probe as an arc and states how many matches each driving row found, such as "Acme id=1 → 2 orders".
- Lessons play about 20% slower by default, and the LRU lesson flashes color changes and fades each conclusion in.

## Bug fixes

- Fixed an issue where the advisor recommended `optimizer_switch='hash_join=on,block_nested_loop=off'` for block nested loop joins. On MySQL 8.0.20 and later the `hash_join` flag has no effect and `block_nested_loop=off` disables the conversion to hash join, so the advisor now recommends an index. MariaDB plans get their own advice.
- Fixed an issue where the MRR suggestion could appear for plans without a secondary index range scan. The advisor now suggests `mrr_cost_based=on` only for those scans and never forces `mrr=on`, which is often slower on SSDs.
- Fixed the glossary entries for Batched Key Access and Block Nested Loop, which now say that Batched Key Access is off by default.
- Fixed an issue where the full scan highlight covered the row text underneath it. It is now drawn as an outline.
- Fixed an issue where six lessons showed no animation in the browser because their JavaScript had a syntax error.
- Fixed an issue where the skip scan and non-unique lookup lessons had broken animations. One called a function that does not exist, and the other drew an element at an invalid position.

## Packaging notes

- Lesson animations use a prebuilt JavaScript bundle that ships with the package. Installing myflames still needs no npm or other dependencies.
