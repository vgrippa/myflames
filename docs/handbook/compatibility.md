# Engine & platform compatibility

myflames supports MySQL 5.7 (end of life, read with stated gaps), 8.0, 8.4 and 9.x, Percona Server for MySQL 8.0 and 8.4 (including Percona XtraDB Cluster), and MariaDB 10.11, 11.4 and 11.8, alongside ProxySQL 2.x and 3.x and Readyset. The desktop app ships for macOS on Apple Silicon, with a Windows x64 installer available as an unsigned preview.

For manual JSON plan generation on MySQL 8.3 and later, run `SET SESSION explain_json_format_version=2` before `EXPLAIN`. Timed JSON analysis (`EXPLAIN ANALYZE FORMAT=JSON`) requires MySQL 8.3 or later (8.4 LTS); on earlier MySQL releases myflames refuses **Run analysis** before sending the query. Connecting to MySQL 5.6 or older shows a warning that myflames supports MySQL 5.7 or later and that results may be missing or inaccurate.

**ProxySQL** supports ProxySQL 2.x and 3.x when connected to a ProxySQL Admin interface. **Readyset** supports Readyset when connected to a Readyset SQL listener (default port `3307`) or admin SQL listener (default port `6036`), including multi-tier topologies across ProxySQL, Readyset, and MySQL or MariaDB servers.

Reading InnoDB Cluster and InnoDB ClusterSet topology and replication health (metadata 2.1.0+) requires no external shell. When MySQL Shell (`mysqlsh`) is installed on this computer (or downloaded with **Get MySQL Shell** in **Settings** > **Client tools** > **Client tools…**), **Cluster** offers reviewed InnoDB Cluster mode switches (MySQL Shell 8.0+), ClusterSet primary switchover, failover and invalidated-cluster rejoin (MySQL Shell 8.0.27+), and incremental-only member rejoin (MySQL Shell 8.1+). MySQL Shell changes are not offered over an SSH tunnel because MySQL Shell connects to the other members directly with the connection's user and password.

## MySQL 5.7

MySQL 5.7 (tested against 5.7.44) is end of life (Oracle Sustaining Support since 2023-10-25). myflames reads 5.7 servers and states in plain sentences what 5.7 lacks rather than reporting errors:

- **Plans and queries**: offline and live estimated plans (`EXPLAIN FORMAT=JSON`) work; **Run analysis** is refused before sending because 5.7 has no `EXPLAIN ANALYZE`; `ALTER TABLE` algorithm prediction (`ALGORITHM=INSTANT` arrived in 8.0.12) is unavailable; **Query digest** Statement digests omit sample SQL text, latency quantiles and CPU time, while **Slow log table** and **Slow log file** work in full.
- **Diagnostics and parameters**: **Locks** reads waiting row locks from `information_schema.INNODB_LOCKS` and `INNODB_LOCK_WAITS`; **Error log** provides log-file guidance (`performance_schema.error_log` arrived in 8.0.22); **Parameters** report no variable source metadata and disable `SET PERSIST` and `RESET PERSIST`, offering `SET GLOBAL` with an option-file line instead; invisible indexes (8.0+) and invisible columns (8.0.23+) are hidden.
- **Operations and accounts**: **Users and roles** manages accounts from 5.7.6+ and notes that roles arrived in MySQL 8.0; administrative privilege checks (`KILL`, `SET GLOBAL`, replica control) check `SUPER`; Group Replication status is read from 5.7.17 while reviewed **Cluster** changes require 8.0.13+; **Maintenance** supports upgrade checks, dumps and restores, without `CLONE` (8.0.17+) or `LOCK INSTANCE FOR BACKUP`.

## MariaDB

myflames is validated against MariaDB 10.11, 11.4 and 11.8:

- **Plans**: parses timed `ANALYZE FORMAT=JSON` and estimated `EXPLAIN FORMAT=JSON` output into the shared operator tree; **Misestimates** flags eligible index-lookup underestimates.
- **Diagnostics and topology**: reads Performance Schema when enabled (required for **Waits**), falls back to `userstat` for index and table I/O counters, reads `metadata_lock_info` for metadata locks, and reads verified local error-log files or shows file guidance. **Replication** inspects multi-source channels (`SHOW ALL SLAVES STATUS`, `gtid_slave_pos`), and **Cluster** inspects MariaDB Galera Cluster (`wsrep_*`, `mysql.wsrep_cluster_members`) and offers reviewed node desync, resync and Primary-component bootstrap actions.
- **Schemas, accounts and tools**: **Schema versions** captures MariaDB sequences, `SQL_MODE=ORACLE` packages and system-versioned tables (listing sequence and versioning differences without generating sync DDL for them), and **Users and roles** supports MariaDB roles, `SET DEFAULT ROLE` and `PUBLIC`. MariaDB accounts using `ed25519` or `parsec` authentication and logical dumps (`mariadb-dump`) require an installed MariaDB client; **Maintenance** provides `mariadb-upgrade` and `mariadb-backup` steps for upgrades and physical backups.

## Percona Server

myflames supports Percona Server for MySQL 8.0 and 8.4 and Percona XtraDB Cluster (PXC):

- **Plans and SQL**: plan formats and **Query editor** features match the corresponding MySQL 8.0 and 8.4 series (`EXPLAIN FORMAT=JSON` on 8.0; `EXPLAIN ANALYZE FORMAT=JSON` and `EXPLAIN FORMAT=JSON` on 8.4).
- **Diagnostics, tuning and upgrades**: **Server** and **Tuning** add Percona `userstat` index and table counters, thread-pool metrics, `log_slow_rate_limit` checks, and Percona Server documentation links in **Parameters**. **Maintenance** > **Upgrade check** reads Percona's package repositories to offer supported Percona Server upgrade targets.
- **Percona XtraDB Cluster**: **Cluster** detects PXC (`wsrep_*` and `performance_schema.pxc_cluster_view`, including on PXC 8.4 where `wsrep_on` is session-only) and displays per-node states from `pxc_cluster_view`; reviewed cluster state changes are not offered on PXC.

## Platforms

- **macOS (Apple Silicon)**: ships as a Developer ID signed and Apple-notarized `.dmg` and `.app` bundle (minimum window size 720 by 520 pixels), with in-place updates when installed in Applications and full SFTP uploads and downloads in **File transfer**. A macOS Intel or Linux desktop binary is not advertised.
- **Windows x64 (preview)**: ships as an unsigned per-user `.exe` installer tested on Windows 11 x64. SSH tunnels run inside a Windows kill-on-close Job Object and stop whenever the app exits or crashes, whereas an in-flight SQL statement or a running `mysqldump`, `mysqlsh` or `CLONE` job can continue until it finishes if the app crashes. In **File transfer**, Windows supports browsing remote folders, signing in with an SSH agent or unencrypted key, and creating, renaming or deleting remote entries; local file uploads and downloads are not available on Windows yet.
- **Client binaries**: both desktop builds include the official MySQL 8.4 LTS `mysql` and `mysqldump` client (with Visual C++ runtime DLLs on Windows) and detect installed MySQL, MariaDB and MySQL Shell installations in standard folders and on `PATH`. Choose **Settings** > **Client tools** > **Client tools…** to inspect or override the selected installation per engine, or choose **Get MySQL Shell** there to download Oracle's pinned MySQL Shell 9.7.0 into myflames's data folder.
