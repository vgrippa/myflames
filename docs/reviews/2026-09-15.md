# Project review: 15 September 2026

Reviewed the Python parser, connection and collection code, advisor, complexity
annotations, CLI, renderers, structured output, comparison logic, teaching
runtime, browser explorer, packaging, and documentation. Fixed the confirmed
issues below and added regression coverage. Existing uncommitted work was retained.

## Findings fixed

| Area | Failure | Correction |
|---|---|---|
| Live plans | Client batch escaping could corrupt JSON containing quoted or backslash-containing SQL. | Request raw output for EXPLAIN; retain escaped row output for other queries. |
| Authentication | Literal password escapes and control characters were interpreted by the option-file parser. | Escape them before writing the client options file. |
| SQL metadata | Comment markers inside strings could hide real tables; hash comments could introduce false ones. | Recognize literals, quoted identifiers, and comments in one pass. |
| MRR advice | Primary-key and covering range scans were treated as secondary-index row-fetch candidates. | Preserve index and covering metadata and exclude those cases. |
| Temporary tables | MySQL TempTable advice applied the MEMORY engine's heap-size limit. | Collect the internal temporary-table engine and select its applicable limits. |
| Buffer advice | Table allocation was described as the query's working set, and buffer sizes were used to imply spills or fixed speedups. | Explain the evidence limits and recommend measured trials. |
| Aggregation | Scalar and streaming aggregation was labeled as sort-based O(n log n). | Account for the linear aggregate pass and model DISTINCT separately. |
| JSON-LD | HTML comment markers in SQL produced invalid JSON escapes. | Use valid Unicode escapes in embedded JSON. |
| SVG | Truncated bar-chart annotations could split an XML entity. | Truncate the source text before escaping it. |
| Timing | Bar charts mixed milliseconds and microseconds, sometimes mutating shared parsed values. | Convert self-time and total time inside the renderer. |
| CLI errors | Some missing/invalid inputs and output-write failures raised tracebacks or returned 1. | Report a diagnostic and return 2. |
| Comparisons | Repeated operator labels lost every occurrence after the first. | Preserve occurrences in both HTML and JSON comparisons. |
| Lesson playback | Pause did not freeze delays; seeking restarted tweens and distorted timing. | Use the same virtual clock for delays, playback, speed changes, and seek offsets. |
| Explorer links | Invalid percent escapes crashed comparisons; empty selections reloaded as defaults. | Parse defensively and preserve empty selections. |
| Fixture generation | The generator deleted existing same-name containers and left its own container on errors. | Refuse collisions and clean up resources created by that run. |

The core fixes were cross-checked against the local MySQL 9.7.0 source checkout:
`mysys/my_default.cc`, `sql/handler.cc`, `sql/sql_tmp_table.cc`,
`storage/temptable/src/handler.cc`, `sql/sql_lex.cc`,
`sql/iterators/composite_iterators.cc`, `sql/item_sum.cc`, and
`sql/join_optimizer/explain_access_path.cc`.

The [Community Server download page](https://dev.mysql.com/downloads/mysql/)
listed 26.7.0. The documentation index also listed 26.7.1, but the Docker tag
`mysql:26.7.1` was unavailable. A fresh pull of the official `mysql:latest` image
ran **MySQL Community Server 26.7.0 on Linux aarch64**, confirmed by both
`mysqld --version` and `SELECT VERSION()`.

Image digest:

```text
mysql@sha256:45abdd9b4144660b5c93a5b7d0ebb21e024f0ba9851ecb4ab43bf83c6bf83592
```

Tests used an isolated Docker container with newly generated sample data. They
covered 68 queries: scans, primary/secondary index lookups, ranges, filters,
sorts, aggregates, joins, semijoins, antijoins, CTEs, window functions, unions,
and combinations of these operations.

- All 68 plans parsed and rendered as all five views: **340 valid SVG outputs**.
- All 68 produced valid sidecars and nonempty digests.
- Comparing each plan with itself produced no regressions or improvements.
- All five live CLI HTML report paths passed, including JSON sidecars and
  parseable embedded JSON-LD.
- Live schema/statistics/session-variable collection passed.
- SQL containing quotes and backslashes retained valid raw JSON.
- Authentication with a password containing literal escape sequences and a
  quote passed against the real server.
- A separate join with `hypergraph_optimizer=on` passed parsing and all five
  renderers. This was a smoke test, not a complete hypergraph corpus.

The container and its anonymous volume were removed after testing. Other local
containers were not modified. Captured plans and test logs remain under `/tmp/`
on the review machine; reproduce them using the commands below.

## Reproduce the corpus checks

Run from the repository root with Docker available:

```bash
docker pull mysql:latest
MYSQL_IMAGE=mysql:latest \
  CONTAINER_NAME=myflames-latest-test \
  OUTPUT_DIR=/tmp/myflames-latest-plans \
  ./scripts/generate-fixtures.sh
MYFLAMES_MYSQL_FIXTURES=/tmp/myflames-latest-plans ./run-tests.sh
```

Use the image digest recorded above instead of `mysql:latest` to select the
same image. The generator writes the actual server version to
`server-version.txt`. See [test instructions](../../test/README.md) for keeping
the container for additional live checks.

## Remaining limitations

- Comparison matches repeated labels by traversal occurrence. Query rewrites
  that move identical operators can still produce ambiguous pairings.
- Table extraction is a lightweight SQL recognizer, not a complete SQL grammar.
- Ordered and multidimensional aggregates without a supported model now omit a
  complexity annotation instead of claiming a linear cost.
- This review did not run a fresh MariaDB server, every historical MySQL release,
  or a Python 3.7 interpreter. Existing MariaDB fixtures and compatibility tests
  ran in the suite, using Python 3.14 locally.
- Browser smoke tests check motion and JavaScript errors; they do not establish
  correctness of every teaching claim or every interaction.
- Server tuning suggestions remain heuristics. The corpus checks validate
  behavior and output integrity, not optimal advice for every workload.
