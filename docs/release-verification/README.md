# Release verification records

Each release X.Y.Z has a record `X.Y.Z.json` in this folder: the evidence that every entry of its release notes page (New features, Improvements, Bug fixes) was verified on the code that ships, through tests, live servers, layout checks and reviews, or with the owner's written acceptance of what stayed unverified. Every bullet must match exactly one item, and each item's plain-text `entry` prefix must match exactly one bullet in its `section`. The schema and the rules are the contract in [DEVELOPER_REFERENCE "Release verification record"](../DEVELOPER_REFERENCE.md#release-verification-record); `python3 scripts/check_release_verification.py X.Y.Z` checks a record, and the Docs and release sync pull-request check runs it when the version changes.

New records require `outcome: "pass"` on every `tests` and `live` entry; tests also require integer counts `executed > 0` and `skipped >= 0` (booleans are not counts), with non-empty `command` and `result` text. A live entry also requires a non-empty `servers` list of non-empty strings and a non-empty `checks` list of objects, each with non-empty `action` and `outcome` strings. Reviews require `verdict: "ship"` or `"ship-with-follow-ups"`; the latter requires a non-empty `follow_ups` list of non-empty strings. Layout still requires four shots (1440 and 720 px, light and dark), SHA-256 values and `looked_at: true`. The required `needs`, owner acceptance of missing evidence and commit ancestry checks still apply; owner acceptance does not override a failed evidence entry.

After an evidence commit, only release version values may change in `pyproject.toml` (`[project] version`), `myflames/__init__.py` (`__version__`), `apps/desktop/package.json` (`version`) and `apps/desktop/package-lock.json` (top-level `version` and `packages[""].version`). All other content and file modes in those files must match. Documentation exemptions are limited to repository-root `*.md`, `apps/*/README.md` and `docs/**` except `docs/schemas/**` and `docs/brand/**`; dependencies, schemas, packaged brand assets and all other files invalidate the evidence when changed.

A published record is validated once, at its own release, against the rules then in force and is never re-validated at a later HEAD, where the existing commit ancestry and final-code checks already reject old evidence; the hardened rules apply to the next record, 3.4.4 onward.
